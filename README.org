* FlagRa

** Video Demo: [[https://www.youtube.com/watch?v=7ajQ-irD1VU]]

** Description

FlagRa is a flag-guessing game written in Flask where you choose a region of the world and try to guess its flags.

The project integrates with the [[https://restcountries.com/][REST Countries API]] to source the data for the flags and countries, which allows the game to dynamically fetch and serve accurate, up-to-date national flags and related countries info.

The application now has a fully functional local backend using SQLite managed via SQLAlchemy. Users can securely register accounts, log in, and maintain their session state. The codebase uses modern Flask best practices, including the [[https://flask.palletsprojects.com/en/stable/tutorial/factory/][Application Factory pattern]] and [[https://flask.palletsprojects.com/en/stable/blueprints/][Blueprints]], to separate game logic from user authentication.

By now, the game is deployed on https://flagra.onrender.com/ and it's using redis to manage sessions. If running locally, ~REDIS_URL~ will not be defined so Flask-Session's filesystem will be used, just follow instructions in [[id:07c7f744-c2a9-4cb5-907b-2a4aa5b3c6db][Installation & Usage]].

** Files

- [[file:app.py][app.py]]
  The Application Factory. It initializes the Flask app, configures environment variables, connects the database, sets up the session, and registers the blueprints.
  
- [[file:auth.py][auth.py]]
  The authentication blueprint. It manages user registration (password hashing via Werkzeug), login validation, and logout.
  
- [[file:game.py][game.py]]
  The game blueprint. Contains the core game loop, API fetching logic, and manages the user's active gameplay session and score tracking.

- [[file:models.py][models.py]] & [[file:database.py][database.py]]
  Defines the database instance and the SQLAlchemy ORM schema, currently housing the ~User~ model to store account credentials securely.
  
- [[file:restcountries.json][restcountries.json]]
  Local data cache. Every time the server starts it tries to get a new version of the data using the ~requests~ library. If it fails, uses this backup.
  
- [[file:requirements.txt][requirements.txt]]
  Python dependencies to run the application, generated with ~pip freeze~.
  
- [[file:templates/][templates/]]
  Contains all HTML template files, including game views, user history and auth forms.
  
- [[file:static/][static/]]
  Contains menu images, a [[file:static/css/style.css][CSS stylesheet]] and a [[file:static/js/script.js][JavaScript script]] (they handle theme switching).
  
** Routes 

*** Game Routes (game.py)

- ~/~: Renders the main menu (~index.html~), where the user selects the region and the number of alternatives.
  
- ~/setup~: Handles the form submission from the main menu (POST). It filters flags based on the region, shuffles the valid IDs into a queue, resets the user's score, and redirects to ~/play~.
  
- ~/play~: The main game loop (~play.html~). It grabs the current flag, selects incorrect alternatives, shuffles choices, stores the correct answer in the session, and awaits the user's guess.
  
- ~/check~: Evaluates the user's guess (POST). Increments the score if correct, appends data to the session history, flashes messages (right or wrong), and redirects back to ~/play~ (GET) for the next round.
  
- ~/results~: The end-game screen (~results.html~). Retrieves the final score, total rounds played, and guess history when the flag queue is empty.

*** Authentication Routes (auth.py)

- ~/register~: Displays the register form (GET) and processes new user registration, inserting the user in the database (POST).
  
- ~/login~: Displays the login form (GET) and securely authenticates returning users, mapping their database ID to the active Flask session (POST).
  
- ~/logout~: Safely clears the user's active session and redirects them back to the main menu.

** Installation & Usage
:PROPERTIES:
:ID:       07c7f744-c2a9-4cb5-907b-2a4aa5b3c6db
:END:

#+begin_quote
[!NOTE]
Before running the application, it's recommended to set up your local environment variables.
If you skip this step, the app will still run using a fallback placeholder key (~42069~). This is perfectly fine for local gameplay and testing. However, keep in mind that the ~SECRET_KEY~ is used by Flask to securely sign session cookies, so it must be strong and unique in a production environment.
#+end_quote

First, generate a secure secret key:

#+begin_src shell
  python -c "import secrets; print(secrets.token_hex(24))"
#+end_src

Then, create a file named ~.env~ in the project root and add your newly generated key:

#+begin_src shell
  SECRET_KEY=<paste-your-generated-key>
#+end_src

To run the game on your machine, set up the virtual environment, initialize the database, and start the Flask app:

#+begin_src shell
  source .venv/bin/activate       # activate virtual environment
  pip install -r requirements.txt # install dependencies
  flask db upgrade                # initialize the local SQLite database
  python app.py                   # runs app @ localhost:5000
#+end_src

Then just open your browser at [[http://localhost:5000/]] and have fun!
